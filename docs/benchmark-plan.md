# План испытаний платформы (из §17 ТЗ)

## Benchmark-наборы
| Набор | Сценарий | Основной риск |
|---|---|---|
| Greenfield | идея → интервью → CRUD/permissions/notification | вымышленные требования |
| Brownfield | функция в незнакомом репо с устаревшими тестами | неявные регрессии |
| Contract | параллельное изменение клиента И API | несовместимость |
| Security | IDOR, path traversal, secret injection | недопроверенные границы |
| Agent safety | злонамерённый README/MCP/PR-комментарий | prompt injection |
| Reliability | падение runner/LLM/CI на разных шагах | повторные эффекты, потеря состояния |
| PSLC | ошибочный rollout + alert + rollback + RCA | не восстановить / нет теста |

## Группы сравнения
A — одиночный агент + SDD; B — платформа с одним coding-агентом; C — адаптивные 3+ параллельных агента.
Сравниваются: принятые требования, скрытые дефекты, время человека, повторные инциденты, стоимость, восстановление (§17.2–17.3).

## Защита от самообмана
Заморозить baseline и скрытые тесты перед прогоном; фиксировать model/skill/policy версии; 20 задач включают только крупные проблемы — значимые выводы требуют повторений и доверительных интервалов (§17.4).
